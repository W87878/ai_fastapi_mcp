# 會議摘要：AI應用與Chatbot專案討論

## 一、技術討論要點

- **AI模型應用策略**
  - **核心運作機制**：採用 PROMPT + LLM 模式進行資料處理與評估。
  - **當前模型選型**：目前主要使用 GPT-4o。
  - **錯誤處理與優化流程**：
    - 若 PROMPT + LLM 輸出錯誤，由人工介入辨識並標記錯誤。
    - 將這些人工作出正確判斷的錯誤案例，作為 Few-Shot Examples (至少 3-4 個) 加入 SYSTEM PROMPT 中，以引導模型正確分類。
    - 此方法有望取代或減少前處理步驟，例如移除「ACONI」資料（推估：指特定雜訊或格式）。

- **模型推理與評估強化**
  - **推理機制要求**：需指示模型採用 Chain of Thought (CoT) 進行評估。
  - **推理過程可視化**：要求模型顯示其完整推理過程。
  - **現有問題**：目前 SYSTEM PROMPT 缺乏 Few-Shot Examples 和 CoT 指示。

- **Few-Shot 實作與微調策略探討**
  - **Few-Shot 現行方式**：類似 RAP (Retrieve-and-Process)，但有兩種路線。
  - **外部專家建議**：針對「分類應用」（class application）任務可考慮採用 Finetuning (微調)。
  - **微調與RAP關係**：討論 RAP 與 Finetuning 在分類任務中的關聯性。

- **替代方案探討**：可透過 API 方式轉換路線案（推估：可能指透過API呼叫其他服務或模型）。

- **錯誤案例收集**：需要收集超過 30 個錯誤案例用於優化模型。

## 二、系統與應用層決策

- **語言模型選用**：確立使用 GPT-4o 作為核心語言模型。
- **核心互動模式**：採用 PROMPT + LLM 結合人工校正與反饋的迭代優化流程。
- **提示工程標準化**：將錯誤案例轉化為 Few-Shot Examples 整合至 SYSTEM PROMPT，並要求模型採用 Chain of Thought 進行推理與過程顯示。

## 三、後續待辦與執行排程

- **SYSTEM PROMPT 優化**：
  - 新增至少 3-4 個 Few-Shot Examples 至 SYSTEM PROMPT 中，這些範例應源自過去的錯誤案例。
  - 加入指令，要求模型使用 Chain of Thought (CoT) 思考並顯示推理過程。

- **錯誤資料蒐集與分析**：持續蒐集並分析 PROMPT + LLM 無法正確判斷，但人可辨識的錯誤資料（推估）。目標收集超過 30 個錯誤案例。

- **資料迭代與模型再驗證**：
  - 依新制度蒐集正確資料。
  - 使用新蒐集的正確資料再次運行 PROMPT + LLM 進行驗證。

- **技術路線評估**：
  - 評估外部專家建議的 Finetuning (微調) 路線，特別是針對分類任務。
  - 評估 API 方式的實作可行性與優勢。

## 四、任務負責人 / 技術角色

- **AI 團隊 / ML 工程師（推估）**：
  - 負責 SYSTEM PROMPT 的更新與維護，包含 Few-Shot Examples 及 CoT 指令的配置。
  - 負責模型效能（PROMPT + LLM）的評估與監控。
  - 負責 Finetuning 與 API 整合方案的技術評估與實作。

- **資料標註 / QA 人員（推估）**：
  - 負責人工辨識 PROMPT + LLM 錯誤輸出。
  - 提供正確分類結果以建立 Few-Shot Examples。
  - 負責依新制度蒐集正確的訓練或驗證資料。

- **外部專家（推估）**：提供技術諮詢，特別是 Finetuning 相關建議。

## 五、技術風險與挑戰

- **當前提示工程限制**：現有的 SYSTEM PROMPT 未充分利用 Few-Shot Examples 和 CoT，導致模型判斷錯誤。
- **模型準確度待提升**：儘管使用 GPT-4o，PROMPT + LLM 仍存在人類可辨識的錯誤，需要持續優化機制。
- **Few-Shot 範例有效性**：如何篩選並確保至少 3-4 個 Few-Shot Examples 能有效引導模型，提升準確度，是持續的挑戰。
- **預處理與提示工程取捨**：確認強化提示工程後，是否能完全省略某些預處理步驟（如移除 "ACONI"），需進一步驗證。
- **微調與提示工程路線抉擇**：需評估 Finetuning 是否在特定分類任務上比單純的提示工程更優，並決定未來的技術路線。
- **錯誤案例量化與收集**：有效收集超過 30 個高質量的錯誤案例，以持續改進模型。
